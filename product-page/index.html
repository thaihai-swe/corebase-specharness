Why CoreBase SpecHarness Exists: The Spec-Anchored Thesis

Modern AI coding agents excel at generating code but routinely fail at long-term software discipline: they jump straight to editing files, lose context across long conversations, invent phantom requirements, declare work complete without verification, and leave behind zero inspectable reasoning.

CoreBase SpecHarness solves this at the root. It is copied directly into an adopter repository as a self-contained kit. It introduces an embedded Python CLI and 11 peer skills that force work through an inspectable 6-phase pipeline (Discovery → Specification → Architecture → Breakdown → Execution → Closeout). Repository markdown files are the single system of record, while the CLI enforces mechanical gates and context bounds.

The Five Non-Negotiable Engineering Invariants

CoreBase SpecHarness mechanically enforces these rules through CLI validators and the state engine:

01

No Code Without Spec & Plan

Coding is prohibited until spec.md, plan.md, and tasks.md exist under artifacts/features/<slug>/ with 100% AC coverage.

02

Single Active Task Execution

During implementation, exactly one task must be In Progress at a time via task-start. Task jumping without checkpointing is rejected.

03

Fresh Evidence on Task Completion

task-done requires explicit --evidence with test or compilation output. Asserting done without fresh proof is rejected.

04

Mechanically Protected Done

Setting status.md to Done is permitted only after inline verification passes and a ## Post-Ship Sync is recorded in session-extracts.md.

05

Advisory Mode Never Authorizes Closeout

When gates are unconfirmed, advisory verification exits 0 for inspection but reports details.verified: false, preventing closeout without explicit override.

2. The Problem & The 3-Layer Thesis

The AI Coding Trap

AI models have reached high reasoning capability, yet agentic software projects frequently collapse into unmaintainable states. The failure is not intelligence; it is boundary collapse:

Dimension Ad-Hoc Chat Agent CoreBase SpecHarness Spec-Driven Kit
System of Record Transient chat conversation context (easily lost) Durable markdown artifacts in repository files
Context Window Bulk dumps of hundreds of files (token waste & hallucination) Budget-capped compiler with session auto-delta (60-80% token savings)
Requirements Vague chat prompts interpreted differently each turn Formal spec.md with 3-wave grilling and numbered AC-* IDs
Task Execution Uncontrolled bulk edits across unrelated files Atomic single-task loop (task-start → edit → proof → task-done)
Verification "Looks good to me!" without running real commands Mechanical argv gates + review.md two-axis verification matrix
Knowledge Retention Forgotten immediately when the chat session ends Durable repository memory (PKB, heuristics, ADRs, domain packs)

The Three-Layer Separation of Concerns

CoreBase SpecHarness strictly decouples human/agent judgment from declarative contracts and deterministic code:

Layer 1

Agent Procedures (Markdown)

skills/<name>/SKILL.md + skills/_shared/

Guides agent reasoning, intake grilling, modular design heuristics, and output formatting. Owned by human & agent judgment.

Layer 2

System Contracts (Declarative YAML/JSON)

references/context-routes.yaml + state-machine.yaml

Single source of truth for routing, prerequisites, artifact schemas, and lifecycle state tokens. Immune to prompt injection.

Layer 3

Deterministic Mechanics (Stdlib Python CLI)

corebase-specharness/scripts/core/cli.py

Enforces budgets, computes fingerprint diffs, parses task graphs, executes argv gates, and logs audit runs. No external daemon required.

3. How It Works (One-Minute Overview)

The Core Execution Loop

Features progress predictably through a bounded 4-step loop from idea to shipping:

1. Enter Skill

skill-enter

Agent selects a named skill. The CLI verifies prerequisites, initializes status.md, resumes session, and compiles a bounded context pack.

python3 corebase-specharness/scripts/core/cli.py skill-enter \
  --skill spec-plan --feature auth-oauth --intent "design oauth provider"
2. Produce Artifact

Follow Procedure

Agent follows SKILL.md to inspect bounded code, design module seams, and write required artifacts (analysis.md, spec.md, plan.md, tasks.md).

3. Check Readiness

artifact-check

CLI evaluates structural headings and enforces 100% bidirectional traceability between Acceptance Criteria and Tasks.

python3 corebase-specharness/scripts/core/cli.py artifact-check \
  --feature auth-oauth --skill spec-plan --trace
4. Exit & Handoff

skill-exit

CLI confirms required output files exist, transitions lifecycle state, checkpoints the session, and enforces explicit handoff to the next peer skill.

python3 corebase-specharness/scripts/core/cli.py skill-exit \
  --skill spec-plan --feature auth-oauth --handoff spec-tasks

5. Memory & Context Compiler

The 8-Step Context Compilation Pipeline

Rather than dumping entire codebases into prompts, context_engine.py dynamically builds a bounded, verifiable context pack for each skill invocation using the single routing authority in references/context-routes.yaml:

1. Universal Bootstrap: Universal policies (caveman.md, core-policies.md) loaded as Must.
2. Route Sources: Declarative files and H2 sections from context-routes.yaml.
3. Feature Evidence: status.md, spec.md, plan.md for active feature.
4. Task Excerpt: Slimmed single-task payload when --task T-NNN is supplied.
5. Add-Sources: Validated repo-relative paths passed via repeatable --add-source.
6. Domain Memory: Triggered on keyword intersection with glossary.md.
7. Local Retrieval: Bounded, path-scoped search with secret pattern redaction.
8. Budget Pruning: Must sources guaranteed; Should sources dropped on overflow.

Deterministic Token Budgets & Thresholds

Parameter Configured Value Operational Purpose
max_injected_tokens 6000 tokens Upper ceiling for any single compiled context pack payload.
reserve_tokens 1500 tokens Guaranteed reserve buffer for model conversation history and system instructions.
payload_budget 2500 tokens Default fallback budget when skill-specific profile budget is unspecified.
memory_warn_lines 200 lines Advisory threshold for durable memory files (prompts compaction review).
memory_hard_lines 3200 lines Hard mechanical cap on durable memory size across repository memory stores.
timeout_seconds 300s (5 min) Process execution timeout cap for verification gates and doctor checks.

Session Auto-Delta Optimization

CoreBase SpecHarness solves multi-turn token exhaustion by storing SHA-256 fingerprints in .corebase-specharness/sessions/<slug>/session.md. Subsequent skill commands compute fingerprint diffs and re-inject only modified files, saving 60–80% of tokens during task execution. Use --full to bypass caching and force a full reload.

8. The Verification Harness & Closeout

The 4-Part Verification Matrix

The verify command combines mechanical preconditions, artifact schemas, requirement traceability, and repository-native gates into a single verdict:

Loading live verify gate...

Advisory vs. Blocking Enforcement Modes

A

Advisory Mode (verification.mode: advisory)

Default for new installs. Reports missing gates and incomplete tasks as warnings with status: deferred. Exits 0 to allow inspection without breaking scripts, but marks details.verified: false. Does NOT authorize Done.

B

Blocking Mode (verification.mode: blocking)

Strict mode for mature codebases. Any gate failure, broken link, or missing task proof immediately sets status: failed, exits 1, and blocks state progression.

9. Getting Started (Install & Onboarding)

10-Minute Installation Guide

CoreBase SpecHarness requires Python ≥ 3.10 and a Bash-compatible shell. The installer, CLI init, and /starter-init are three distinct operations:

Step Command What it does
1. Install / Upgrade bash kit/corebase-specharness/scripts/install.sh <target> Copies 102 overwrite-owned files, seeds missing copyIfMissing stubs, chmods 3 scripts, and runs doctor.
2. Scaffold Local Dirs python3 corebase-specharness/scripts/core/cli.py init --json Creates missing directories (corebase-specharness/memories/repo, corebase-specharness/memories/domain, corebase-specharness/project, artifacts/features) and missing seed stubs. Never overwrites existing files.
3. Tailor the Repository /starter-init Agent procedure that customizes seeded memory (architecture.md, tech-stack.md, project-knowledge-base.md) and proposes confirmed verification gates. 
# 1. Preview installation with dry-run
bash kit/corebase-specharness/scripts/install.sh /path/to/your-project --dry-run

# 2. Run live installation (copies 102 overwrite files, seeds missing configs)
bash kit/corebase-specharness/scripts/install.sh /path/to/your-project

# 3. Enter target repo, scaffold missing dirs, and verify installation health
cd /path/to/your-project
python3 corebase-specharness/scripts/core/cli.py init --json
python3 corebase-specharness/scripts/core/cli.py doctor --json

Package Health Surface (10 Doctor Checks)

  1. manifest: Validates SemVer, keys, missing glob patterns, and shipped files.
  2. ownership: Asserts zero overlap between overwrite and copyIfMissing.
  3. surfaces: Verifies no retired leftovers exist on disk.
  4. context_routes: Validates route fields, phases, states, and source file existence.

  6. providers: Asserts tool provider registry integrity.

  9. configuration: Validates harness-config.yaml schema.

12. FAQ & Common Anti-Patterns

Top 10 Agent Failure Modes & CoreBase SpecHarness Defenses

Failure Mode What Goes Wrong How CoreBase SpecHarness Prevents It
Premature Coding Agent modifies code before understanding requirements. skill-exit fails if spec.md, plan.md, or tasks.md are missing.
Context Exhaustion Agent dumps entire repo into context, causing hallucinations. Bounded Context Compiler with session auto-delta limits context.
Task Jumping Agent works on multiple tasks at once and loses focus. task-start locks exactly one active In Progress task.
Phantom Completion Agent marks tasks done without running tests. task-done rejects completion without fresh --evidence.
Unchecked Closeout Agent closes features without running verification gates. Done requires passing inline verification.
Forgotten Knowledge Hard-won bug fixes and patterns are lost across sessions. Mandatory Post-Ship Sync captures durable lessons in PKB.
Hidden Assumptions Agent guesses missing requirements instead of asking. [:HALT human-in-the-loop brake blocks transitions.
Upgrade Overwrites Kit updates wipe out adopter project configurations. Strict overwrite vs copyIfMissing manifest boundaries.
Advisory False Positives Agent treats exit 0 in advisory mode as a verified pass. Harness explicitly requires details.verified: true for Done.
Vendor Lock-in Kit relies on proprietary cloud services or daemons. Zero runtime dependencies — pure Python 3.10+ standard library.
