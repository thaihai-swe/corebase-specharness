Design thesis

Three layers most agent kits collapse

The agent chooses a skill. The route says what to load and what must exist. The CLI checks files, tokens, and transitions. Nobody in this loop infers the next product decision.

Layer 1 · Procedure

Agent procedures

skills/<name>/SKILL.md

Humans refine how an agent should think: intake, design heuristics, halt rules, and output shape. Markdown is the interface.

Layer 2 · Contract

Declarative routes & lifecycle

context-routes.yaml + state-machine.yaml

Maintainers change what the runtime will load, require, and allow. Immune to prompt injection.

Layer 3 · Mechanics

Deterministic Python CLI

corebase-specharness/scripts/core/cli.py

Budgets, fingerprints, task graphs, argv gates, and atomic writes. Facts, not a hidden workflow runner.

Capabilities

What the kit actually ships

01

Bounded context compiler

Route-declared sources, intent-matched domain packs, and local retrieval with secret redaction. Must sources stay; Should sources drop on overflow. Every pack exposes a selection manifest.

02

Files are the database

Feature state, tasks, sessions, memory, and config live as Markdown, YAML, and JSON the owner can read without the CLI. tasks.md is canonical; tasks.json is its sidecar.

03

One readiness evaluator

phase-check, skill-exit, and verify share one readiness path. Advisory mode reports deferred. Blocking mode fails closed. Done still needs evidence.

04

Single-task implementation

task-start locks exactly one In Progress task. task-done requires fresh --evidence. Jumping without a checkpoint is rejected.

05

Upgrade-safe ownership

Install is copy-with-seed. Kit-owned files overwrite; adopter-owned memory and project stubs seed once. No vendor instruction files are created.

06

Optional providers stay optional

Review and code-intelligence providers default to active: none. The kit never installs provider binaries. /harness-verify still reviews on two axes without them.

Why CoreBase SpecHarness Exists: The Spec-Anchored Thesis

Modern AI coding agents excel at generating code but routinely fail at long-term software discipline: they jump straight to editing files, lose context across long conversations, invent phantom requirements, declare work complete without verification, and leave behind zero inspectable reasoning.

CoreBase SpecHarness solves this at the root. It is copied directly into an adopter repository as a self-contained kit. It introduces an embedded Python CLI and 11 peer skills that force work through an inspectable 6-phase pipeline (Discovery → Specification → Architecture → Breakdown → Execution → Closeout). Repository markdown files are the single system of record, while the CLI enforces mechanical gates and context bounds.

The Five Non-Negotiable Engineering Invariants

CoreBase SpecHarness mechanically enforces these rules through CLI validators and the state engine:

01

No Code Without Spec & Plan

Coding is prohibited until spec.md, plan.md, and tasks.md exist under artifacts/features/<slug>/ with 100% AC coverage.

02

Single Active Task Execution

During implementation, exactly one task must be In Progress at a time via task-start. Task jumping without checkpointing is rejected.

03

Fresh Evidence on Task Completion

task-done requires explicit --evidence with test or compilation output. Asserting done without fresh proof is rejected.

04

Mechanically Protected Done

Setting status.md to Done is permitted only after inline verification passes and a ## Post-Ship Sync is recorded in session-extracts.md.

05

Advisory Mode Never Authorizes Closeout

When gates are unconfirmed, advisory verification exits 0 for inspection but reports details.verified: false, preventing closeout without explicit override.

2. The Problem & The 3-Layer Thesis

The AI Coding Trap

AI models have reached high reasoning capability, yet agentic software projects frequently collapse into unmaintainable states. The failure is not intelligence; it is boundary collapse:

The Three-Layer Separation of Concerns

CoreBase SpecHarness strictly decouples human/agent judgment from declarative contracts and deterministic code:

Layer 1

Agent Procedures (Markdown)

skills/<name>/SKILL.md + skills/_shared/

Guides agent reasoning, intake grilling, modular design heuristics, and output formatting. Owned by human & agent judgment.

Layer 2

System Contracts (Declarative YAML/JSON)

references/context-routes.yaml + state-machine.yaml

Single source of truth for routing, prerequisites, artifact schemas, and lifecycle state tokens. Immune to prompt injection.

Layer 3

Deterministic Mechanics (Stdlib Python CLI)

corebase-specharness/scripts/core/cli.py

Enforces budgets, computes fingerprint diffs, parses task graphs, executes argv gates, and logs audit runs. No external daemon required.

3. How It Works (One-Minute Overview)

The Core Execution Loop

Features progress predictably through a bounded 4-step loop from idea to shipping:

1. Enter Skill

skill-enter

Agent selects a named skill. The CLI verifies prerequisites, initializes status.md, resumes session, and compiles a bounded context pack. 

python3 corebase-specharness/scripts/core/cli.py skill-enter \
  --skill spec-plan --feature auth-oauth --intent "design oauth provider"
2. Produce Artifact

Follow Procedure

Agent follows SKILL.md to inspect bounded code, design module seams, and write required artifacts (analysis.md, spec.md, plan.md, tasks.md).

3. Check Readiness

artifact-check

CLI evaluates structural headings and enforces 100% bidirectional traceability between Acceptance Criteria and Tasks.

python3 corebase-specharness/scripts/core/cli.py artifact-check \
  --feature auth-oauth --skill spec-plan --trace
4. Exit & Handoff

skill-exit

CLI confirms required output files exist, transitions lifecycle state, checkpoints the session, and enforces explicit handoff to the next peer skill.

python3 corebase-specharness/scripts/core/cli.py skill-exit \
  --skill spec-plan --feature auth-oauth --handoff spec-tasks

5. Memory & Context Compiler

The 8-Step Context Compilation Pipeline

Rather than dumping entire codebases into prompts, context_engine.py dynamically builds a bounded, verifiable context pack for each skill invocation using the single routing authority in references/context-routes.yaml. Session auto-delta unions last_context_fingerprint and last_context_slices from session.md before budget math unless --full is passed:

1. Universal Bootstrap: Universal communication and core policies (caveman.md, core-policies.md) loaded as Must.
2. Route Sources: Declarative files and H2 sections from references/context-routes.yaml.
3. Feature Evidence: status.md, spec.md, plan.md, and other route-declared feature files.
4. Task Excerpt: Compact single-task payload when --task T-NNN is supplied (omits full tasks.md).
5. Add-Sources: Validated repository-relative paths passed via repeatable --add-source.
6. Domain Memory: Selected when keywords intersect corebase-specharness/memories/domain/<name>/glossary.md triggers.
7. Local Retrieval: Bounded, path-scoped evidence search with automated secret pattern redaction.
8. Auto-Delta then Budget Math: Unchanged files and H2 slices are skipped first. Must sources stay; Should sources drop on overflow. Effective budget capped by max_injected_tokens (6000) - reserve_tokens (1500) = 4500.

Deterministic Token Budgets & Thresholds

Parameter Configured Value Operational Purpose
max_injected_tokens 6000 tokens Upper ceiling for any single compiled context pack payload.
reserve_tokens 1500 tokens Guaranteed reserve buffer for model conversation history and system instructions (effective payload ceiling = 4500).
payload_budget 2500 tokens Default fallback budget when skill-specific profile budget is unspecified.
session_warn_tokens 40000 tokens Advisory threshold for cumulative session token consumption.
session_hard_tokens 80000 tokens Hard mechanical ceiling for cumulative session token consumption.
memory_warn_lines 200 lines Advisory threshold for durable memory files (prompts compaction review).
memory_hard_lines 3200 lines Hard mechanical cap on durable memory size across repository memory stores.
timeout_seconds 300s (5 min) Process execution timeout cap for verification gates and doctor checks.

Channel caps apply to non-Must sources after skip-before-budget: max_bootstrap_tokens: 1200, max_project_tokens: 1200, max_feature_tokens: 1600, max_retrieved_tokens: 1000, max_source_excerpt_tokens: 400, max_retrieval_files: 4.

Session Auto-Delta & The --full Contract

SHA-256 fingerprints live in .corebase-specharness/sessions/<slug>/session.md (last_context_fingerprint, last_context_slices). The compiler never inspects the live chat window. Those two stores do not talk to each other.

User action Chat still has the files? What the user types What the agent does
Same uncompacted chat, same feature Yes The next skill Omit --full (delta)
After conversation compact Often no Skill + reload context Pass --full once
First skill of a new chat, same feature No First skill + reload context Pass --full on first enter
New feature slug No (empty hashes) The skill Omit --full (full pack is automatic)

--full reloads that skill’s complete route pack. It does not wipe session.md, start a new feature, or replay earlier skills. session-end does not clear fingerprints. Compacting a memory file on disk is not conversation compact — that file’s hash changes and is re-injected if the next route still needs it.

Canonical Task Format & Execution Loop

Never edit task checkboxes or tasks.json by hand. tasks.md is canonical; tasks.json is a generated sidecar and a read-only fallback when tasks.md is missing. IDs are T-NNN only. Older TASK-* IDs are not parsed. 

- [ ] T-001 Add retry budget calculation
  - Status: Not Started
  - Depends on:
  - Covers: AC-01
  - Validation evidence:

The implement loop after skill-enter --skill spec-implement. Do not re-run skill-enter between tasks: 

python3 corebase-specharness/scripts/core/cli.py task-check --feature <slug>
python3 corebase-specharness/scripts/core/cli.py task-start --feature <slug> --task T-001
python3 corebase-specharness/scripts/core/cli.py context-load \
  --skill spec-implement --feature <slug> --task T-001 --intent "..."
# edit + prove
python3 corebase-specharness/scripts/core/cli.py task-done \
  --feature <slug> --task T-001 --evidence "pytest tests/test_retry.py passed"
From Allowed next statuses
Not Started Not Started, In Progress, Blocked, Deferred
In Progress Not Started, In Progress, Blocked, Done, Deferred
Blocked Not Started, In Progress, Blocked, Deferred
Done Done, In Progress (reopen)
Deferred Deferred, Not Started, In Progress

[:HALT in spec.md, plan.md, or tasks.md blocks all task mutations until it is removed. Named tokens below are procedure stop conditions. The runtime only looks for the substring [:HALT.

Marker Owning skill / meaning
[:HALT INCONCLUSIVE] /spec-research — evidence is too thin to exit as complete.
[:HALT ADR CONFLICT: ADR-NNN] /spec-requirements — a proposed AC contradicts a recorded ADR.
[:HALT STALE] /spec-implement — spec was amended after plan approval.
[:HALT SYNC REQUIRED] /harness-verify — ## Post-Ship Sync is missing from session-extracts.md.
[:HALT SECURITY] Any skill — a security policy stop that a human must resolve.

Advisory vs. Blocking Enforcement Modes

A

Advisory Mode (verification.mode: advisory)

Default for new installs. Reports missing gates and incomplete tasks as warnings with status: deferred. Exits 0 to allow inspection without breaking scripts, but marks details.verified: false. Does NOT authorize Done.

B

Blocking Mode (verification.mode: blocking)

Strict mode for mature codebases (fallback when key is missing). Any gate failure, broken link, or missing task proof immediately sets status: failed, exits 1, and blocks state progression.

Manifest Ownership & Backup Invariants

kit/manifest.json defines two ownership groups. Upgrades replace only kit-owned files; adopter configuration and durable memory are never overwritten.

Group Paths / Patterns Upgrade behavior
files.overwrite (kit-owned) manifest.json, README.md, AGENTS.md, EXTERNAL_SKILLS.md, skills/** plus the .agent/skills/** overwrite mirror, references/context-routes.yaml, references/tool-providers-registry.json, corebase-specharness/scripts/core/**, corebase-specharness/scripts/install.sh, corebase-specharness/rules/**, corebase-specharness/project/state-machine.yaml, corebase-specharness/scripts/validate-static-audit.py Backed up, then replaced on upgrade.
files.copyIfMissing (adopter-owned) corebase-specharness/MASTER_INDEX.md, corebase-specharness/memories/repo/**, corebase-specharness/project/architecture.md, corebase-specharness/project/tech-stack.md, corebase-specharness/project/product-sense.md, corebase-specharness/project/project-constraints.md, corebase-specharness/project/glossary.md, corebase-specharness/project/harness-config.yaml, corebase-specharness/project/tool-providers.md, artifacts/features/README.md, corebase-specharness/memories/domain/**, corebase-specharness/memories/archive/** Seeded once. Existing files are preserved untouched.

Backups live at .corezero-backup-<random>/ (allocated via mktemp -d, not a timestamp). They contain only overwritten files, not the whole repo, and are never automatically added to .gitignore. init outputs onboarding_readiness (detected stacks, native instruction files, confirmed gates, and unknowns).

  7. upgrade_contracts: Validates kit-owned escape transitions.
  8. static_audit: Asserts reachability of all shipped core.* modules.
  9. configuration: Validates harness-config.yaml schema.

12. FAQ & Common Anti-Patterns

Top 10 Agent Failure Modes & CoreBase SpecHarness Defenses

Failure Mode What Goes Wrong How CoreBase SpecHarness Prevents It
Premature Coding Agent modifies code before understanding requirements. skill-exit fails if spec.md, plan.md, or tasks.md are missing.
Context Exhaustion Agent dumps entire repo into context, causing hallucinations. Bounded Context Compiler with session auto-delta limits context.
Task Jumping Agent works on multiple tasks at once and loses focus. task-start locks exactly one active In Progress task.
Phantom Completion Agent marks tasks done without running tests. task-done rejects completion without fresh --evidence.
Unchecked Closeout Agent closes features without running verification gates. Done requires passing inline verification.
Forgotten Knowledge Hard-won bug fixes and patterns are lost across sessions. Mandatory Post-Ship Sync captures durable lessons in PKB.
Hidden Assumptions Agent guesses missing requirements instead of asking. [:HALT] human-in-the-loop brake blocks transitions.
Upgrade Overwrites Kit updates wipe out adopter project configurations. Strict overwrite vs copyIfMissing manifest boundaries.
Advisory False Positives Agent treats exit 0 in advisory mode as a verified pass. Harness explicitly requires details.verified: true for Done.
Vendor Lock-in Kit relies on proprietary cloud services or daemons. Zero runtime dependencies — pure Python 3.10+ standard library.
